지금 이 글을 어디서 읽고 계신지 모르겠지만, 이건 원래 내 옵시디언 볼트 안에 있던 파일이다. 마지막 편은 **이게 어떻게 여기까지 왔는지**에 대한 것이다.

그리고 이 얘기는 기능 소개가 아니라 사고 방지 장치에 대한 것이다. 내 볼트에는 회사 시스템 이름, 사람 이름, 사설 IP, 장애 기록이 들어 있다. **잘못 올린 건 지워도 캐시와 검색엔진에 남는다.**

## 기존 노트를 다듬어 올리지 않는다

이 시리즈에서 제일 강하게 주장하고 싶은 게 이거다.

"볼트 노트에서 사적인 부분만 지우고 발행한다"는 방식은 **denylist**다. 지워야 할 것을 빠짐없이 안다는 전제 위에 서 있다. 그런데 그 전제는 항상 틀린다. 규칙은 현실보다 늦고, 새로운 종류의 민감 정보는 계속 생기고, **한 번만 놓치면 끝이고 놓쳤는지는 올린 다음에야 안다.**

공개용을 처음부터 새로 쓰면 **allowlist**가 된다. 기본값이 "아무것도 안 나감"이고, 내가 손으로 넣은 것만 나간다.

그래서 이 볼트에는 `publish`라는 타입이 따로 있고, 규칙이 하나 있다. **기존 노트를 이 타입으로 승격하지 않는다.** 참고해서 새로 쓴다. 이 시리즈 여덟 편도 전부 볼트 문서를 보면서 새로 쓴 것이지 노트를 옮긴 게 아니다.

번거롭다. 그런데 이 번거로움이 안전장치의 본체다.

## publish 타입은 다른 필드를 쓴다

다른 타입과 뭐가 다른지가 곧 "공개"라는 축이 무엇인지를 보여준다.

```yaml
---
type: publish
created: 2026-08-09
status: active
slug: obsidian-lifeos-build-8
tags:
  - lifeos
  - obsidian
---
```

**`persona`가 없다.** 3편에서 말한 그 이유다. persona는 "이게 어디서 나왔나"(출신)를 묻고 발행은 "누가 읽나"(청중)를 묻는다. 축이 직교한다. 게다가 이 타입은 전부 공개용이라 값을 넣어봤자 상수가 되어 아무 정보도 안 담는다. 출신이 궁금하면 `## 관련`의 원본 링크를 타고 가면 된다.

**`maturity`도 `description`도 없다.** 공개본에 성숙도 축은 의미가 없고, 설명은 Quartz가 본문에서 자동 생성한다.

**`slug`이 URL을 결정한다.** 제목은 파일명이라 언제든 바꿔도 되지만 **`slug`은 한 번 발행하면 고정이다.** 이 구조가 마음에 든다. 제목을 고치고 싶을 때 URL이 깨질까 봐 망설이지 않아도 된다.

**`tags`는 볼트의 태그와 의미가 다르다.** 3편에서 태그를 "허브가 없는 시리즈의 임시 이름표"로 재정의했는데, 여기 태그는 그냥 사이트 분류고 값이 있으면 태그 페이지가 생긴다. 같은 이름의 필드지만 사는 세계가 달라서 규칙도 따로 간다.

그리고 **홈을 뺀 모든 발행본에 `tags` 속성이 있어야 한다. 값은 비어도 된다.** 값이 아니라 속성을 요구하는 이유는 3편의 "빈 선택 필드는 키를 남긴다"와 같다. 속성이 있어야 편집기에 자리가 보이고 나중에 채운다.

## 폴더가 유일하게 의미를 갖는 곳

1편에서 폴더를 전부 지웠는데, 딱 한 군데 폴더가 남았고 거기서는 폴더가 **가장 중요하다.**

```
Publish/obsidian/글.md  (slug: foo)  →  /obsidian/foo
```

**`Publish/` 아래 폴더 구조가 그대로 사이트 URL 경로가 된다.** 폴더를 만들면 경로가 되고, Quartz가 폴더별 목록 페이지도 자동으로 만든다.

그래서 발행 노트를 만드는 템플릿만 유일하게 **파일을 이동시킨다.** 만들 때 어느 폴더인지 물어보고 그 자리로 옮긴다. 이때 신경 쓴 게 둘이다.

**실재하는 폴더만 후보로 보여준다.** 없는 폴더를 목록에 하드코딩해두면 지운 폴더가 유령처럼 계속 나타난다.

**같은 이름이 있으면 번호를 붙인다.** 덮어쓰지 않는다. 발행본을 날리는 사고를 막는 것이고, 이런 건 한 번 겪으면 늦다.

폴더 없는 볼트를 만들어놓고 여기만 폴더가 살아남은 게 아이러니한데, 이유가 분명하다. **볼트 안에서 폴더는 내가 만든 분류지만, 여기서 폴더는 외부 시스템(URL)이 요구하는 구조다.** 1편에서 예외로 둔 세 폴더와 같은 성격이다.

## 링크 규칙 하나 때문에 생긴 예외

**발행 노트는 발행 노트만 링크할 수 있다.** 볼트 노트를 가리키면 사이트 빌드가 깨진다. 존재하지 않는 페이지로 가는 링크가 되기 때문이다.

그런데 이러면 옵시디언 쪽에서 원본 노트와의 연결이 끊긴다. 이 글의 근거가 된 볼트 문서를 나중에 고칠 때, 이 글이 있다는 걸 알 방법이 없다.

그래서 **`## 관련` 섹션 하나만 예외**로 뒀다. 거기서는 볼트 노트를 링크해서 옵시디언 백링크를 얻고, **발행할 때 그 섹션을 통째로 잘라낸다.** 사이트에는 안 나간다.

한 군데만 예외로 열고 나머지는 전부 막는 방식이다. 예외를 여러 개 만들면 결국 규칙이 없는 것과 같아진다.

## 발행 버튼을 막는 검사들

미리보기를 누르면 계획을 세우는데, 이 시점까지 **디스크에 아무것도 쓰지 않는다.** 그리고 아래 중 하나라도 걸리면 목록만 보여주고 **발행 버튼이 비활성화된다.**

| 검사 | 막는 것 |
|---|---|
| 볼트 링크 | 발행 노트가 볼트 노트를 가리킴 (`## 관련`은 예외) |
| tags 속성 누락 | 홈을 뺀 발행본에 `tags` 속성 없음 |
| slug 누락 | 출력 파일명을 정할 수 없음 |
| 출력 경로 중복 | 두 노트가 같은 파일을 덮어씀 |
| 홈 부재 | `slug: index`가 없어 사이트 루트가 404 |
| 시크릿 | 토큰·자격증명·사설 IP·이메일·개인키 |
| 첨부 이상 | 볼트에 없는 파일, 사이트로 못 내보내는 형식 |

**왜 경고가 아니라 차단인가.** 경고는 급할 때 무시하게 된다. 그리고 발행은 되돌릴 수 없는 동작이다. 4편에서 파일 삭제 확인창은 껐다고 했는데, 기준이 같다. **되돌릴 수 있으면 확인을 없애고 되돌릴 수 없으면 막는다.**

"출력 경로 중복"이 의외로 중요하다. 서로 다른 두 글에 같은 `slug`을 쓰면 한쪽이 조용히 사라진다. 시리즈를 쓰다 보면 복사해서 시작하기 때문에 실제로 일어난다.

## 이미지 안은 검사할 수 없다

여기가 이 시스템에서 제일 정직하게 적어야 하는 부분이다.

시크릿 검사는 **텍스트만 본다.** 사설 IP, 이메일, API 토큰, 개인키를 정규식으로 잡는다. 그런데 **스크린샷 안에 있는 건 아무도 못 막는다.** 터미널 캡처 한 장에 호스트명과 내부 IP가 그대로 들어 있어도 검사는 통과한다.

그래서 첨부가 있으면 미리보기에 경고를 띄운다. "첨부 N개를 함께 내보낸다 — 이미지 안의 내용은 검사되지 않는다. 눈으로 확인할 것."

이 경고를 넣은 이유는 단순히 알려주려는 게 아니다. **자동 검사가 있으면 사람이 안 본다.** 텍스트는 막아주는데 이미지는 안 막아준다는 비대칭을 그대로 두면, "검사를 통과했으니 괜찮겠지"가 되고 그 순간이 제일 위험하다.

## 손으로 지우지 않는다

`content/` 폴더에서 파일을 지우는 건 위험한 동작이다. 잘못 지우면 사이트에서 페이지가 사라진다.

그래서 **이 도구가 만든 파일 목록을 따로 들고 있고, 그 목록에 있는 것만 지운다.** 손으로 둔 파일이 섞여 있어도 건드리지 않는다. 첨부 이미지도 이 목록에 들어간다. 글에서 이미지를 빼면 다음 발행에서 사이트에서도 사라지고, 빈 폴더는 정리된다.

원칙 하나가 뒤에 있다. **`content/`는 통째로 파생물이다.** 언제든 다시 만들어지고, 거기서 손으로 고친 건 다음 실행에 사라진다. 고칠 곳은 볼트의 원본뿐이다.

## 왜 셸 스크립트가 아니라 플러그인인가

처음엔 파이썬 스크립트였다. 갈아엎었다.

| | 스크립트 | 플러그인 |
|---|---|---|
| 경로 | 코드에 하드코딩 | **설정 값** |
| 프론트매터 파싱 | 자체 정규식 파서 | **옵시디언의 메타데이터 캐시** |
| 발행 전 확인 | 텍스트 목록 | **줄 단위 diff** |
| 실행 | 터미널 전환 | 명령 팔레트 / 리본 아이콘 |

프론트매터 파싱이 결정적이었다. 정규식으로 YAML을 파싱하면 언젠가 틀린다. 옵시디언은 이미 정확한 파서를 갖고 있고 플러그인은 그걸 그냥 쓸 수 있다.

그리고 옛 스크립트는 **삭제했다.** 같은 로직이 두 곳에 있으면 반드시 어긋나고, 실제로 사설 IP 정규식 버그가 한쪽에만 있는 상태가 나왔다. 검사 도구가 두 개인데 한쪽만 구멍이 있으면 그건 검사가 없는 것보다 나쁘다.

7편에서 적었듯 이 플러그인은 볼트 안에 살고 빌드 과정이 없다. 파일 세 개다.

```
.obsidian/plugins/quartz-publish/
├─ manifest.json
├─ main.js       # 순수 CommonJS. 번들러도 node_modules도 없다
└─ styles.css    # 하드코딩한 색 0 — 전부 옵시디언 CSS 변수
```

## 밟은 함정들

전부 실제로 겪은 것이다. 비슷한 걸 만들 사람에게는 이 절이 제일 쓸모 있을 것이다.

**자리표시자를 맨 숫자로 두면 안 된다.** 본문을 변환할 때 코드 블록을 잠시 다른 문자열로 치환해두는데, 이때 `0`, `1` 같은 숫자를 쓰면 복원할 때 쓰는 정규식이 **본문의 숫자까지 먹는다.** 글에 "2026년"이라고 썼는데 거기에 코드 블록이 들어가는 식이다. 본문에 절대 없을 제어 문자로 감싸야 한다.

**macOS GUI 앱의 PATH에는 `node`가 없다.** Finder로 띄운 옵시디언은 로그인 셸을 거치지 않아서 nvm이나 homebrew 경로를 모른다. 터미널에서는 되는데 플러그인에서는 "command not found"가 난다. 모든 명령을 로그인 셸로 감싸서 프로필을 태워야 한다. 이래서 이 플러그인은 사실상 맥 전용이다.

**사설 IP 정규식에 공통 꼬리를 붙이면 안 된다.** 접두사마다 남은 옥텟 수가 다르기 때문이다. `10.`으로 시작하는 대역은 뒤에 세 덩어리가 오고 `192.168.`로 시작하는 대역은 두 덩어리가 온다. 하나로 묶어 쓰면 후자를 통째로 놓친다. **보안 검사가 조용히 실패하는 종류의 버그**라 제일 위험했다.

(여담인데 이 문단을 처음 쓸 때 예시 IP를 그대로 적었다가 **내가 만든 검사에 걸려 발행이 막혔다.** 검사가 일하고 있다는 뜻이라 기분이 나쁘지는 않았다.)

**diff는 큰 파일에서 접는다.** 줄 단위 비교 알고리즘이 메모리를 제곱으로 먹어서, 1200줄을 넘으면 계산하지 않고 "생략했습니다"로 표시한다.

**색을 하드코딩하지 않는다.** 전부 옵시디언 CSS 변수만 쓴다. 다크와 라이트, 커스텀 테마에서 같이 살아야 한다. 7편의 CSS 원칙과 같은 얘기다.

## 발행 전에 diff를 본다

이 도구의 존재 이유는 사실 한 줄로 정리된다. **무엇이 나가는지 모르는 채로 나가는 일이 없게 하는 것.**

미리보기 모달에 신규·변경·제거가 숫자로 뜨고, 파일을 누르면 줄 단위 diff가 펼쳐진다. 첨부는 diff를 낼 수 없으니 크기만 표시한다. 여기서 발행을 누르면 그때 파일이 써지고, 로컬 빌드를 한 번 돌려 오류를 잡고, 커밋하고 푸시한다. 커밋 메시지는 자동으로 만들어진다.

로컬 빌드를 끄면 더 빠른데 켜두고 있다. **원격에서 깨지는 것보다 여기서 깨지는 게 낫다.**

## 남은 것

정직하게 적자면 아직 미완성이다.

**이미지 검사는 앞으로도 못 한다.** 사람이 보는 수밖에 없다.

**RSS와 댓글은 최근에야 붙였다.** 사이트 자체는 아직 손볼 데가 많다.

**그리고 이 시리즈를 쓰면서 발견한 게 있다.** 5편에서 적은 것처럼 대시보드 뷰 세 개가 오래된 상태 값을 찾고 있어서 영원히 빈 표다. 스키마를 정리하면서 조회 쪽을 같이 안 고친 것이다. 글을 쓰려고 설정을 전부 다시 읽어보지 않았으면 몰랐을 일이다.

**남에게 설명하려고 정리하는 과정이 점검이 된다.** 이 시리즈를 쓴 부수 효과 중에 이게 제일 컸다.

## 여기까지

1편에서 폴더를 지웠고, 2편에서 할일을 밖으로 뺐다가 다시 붙였고, 3편에서 속성을 설계했고, 4편에서 입력 마찰을 없앴고, 5편에서 찾는 법을 만들었고, 6편에서 그걸 행동으로 잇는 고리를 닫았고, 7편에서 없는 건 만들었고, 8편에서 그중 일부를 밖으로 내보냈다.

한 바퀴다.

정답이라서 적은 게 아니다. **지금 굴러가고 있어서** 적었다. 상황이 달랐다면 다른 결론이 나왔을 것이고, 오래 쓰다 보면 또 갈아엎을 것이다. 실제로 이 여덟 편을 쓰는 동안에도 바뀐 게 있다.
