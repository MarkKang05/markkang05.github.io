옵시디언에 할일을 넣으면 밖에서 안 보이고, Todoist에 넣으면 기록과 끊긴다.

둘 다 쓰면 되지 않나 싶은데, 둘 다 쓰면 **둘 다 안 쓰게 된다.** 같은 할일을 두 군데 적는 순간 어느 쪽이 맞는지 모르게 되고, 모르면 안 보게 된다.

그래서 둘을 붙이는 데몬을 하나 만들었다. 이름은 tnsync다.

## 무엇을 하는가

한 문장으로 쓰면 이렇다.

**옵시디언 앱과 무관하게, 볼트의 마크다운 파일을 직접 읽고 쓰는 파이썬 데몬이 60초마다 Todoist API와 볼트를 대조해 양쪽을 맞춘다.**

```
┌──────────┐   Sync API    ┌──────────────┐   파일 R/W   ┌────────────────┐   Obsidian Sync   ┌────────┐
│ Todoist  │ ◀──────────▶ │ tnsync (Mac) │ ◀──────────▶ │  볼트 (*.md)   │ ◀───────────────▶ │  iPad  │
└──────────┘  (60초 폴링)   └──────────────┘              └────────────────┘                   └────────┘
```

아이패드에서 Todoist로 할일을 체크하면 1분 안에 볼트의 마크다운 파일이 바뀐다. 반대도 된다. **그리고 그동안 옵시디언은 꺼져 있어도 된다.**

전제가 하나 있다. 옵시디언 쪽 할일은 **TaskNotes** 플러그인으로 관리한다. 이 플러그인은 할일 하나를 노트 하나로 만들고 상태·우선순위·일정을 프론트매터에 넣는다. **할일이 그냥 마크다운 파일**이라는 게 이 도구가 성립하는 이유다.

## 왜 기존 플러그인을 안 썼나

옵시디언에도 Todoist 연동 플러그인이 몇 개 있다. 다 같은 한계가 있다.

**플러그인은 옵시디언이 켜져 있어야 돈다.**

내 주 사용환경은 아이패드다. 아이패드에서 할일을 처리하고 맥북 옵시디언을 며칠 안 열면, 그동안 아무것도 동기화되지 않는다. 그리고 며칠 뒤에 앱을 켜는 순간 밀린 변경이 한꺼번에 쏟아지는데, 그때가 제일 사고 나기 좋은 시점이다.

그래서 조건을 하나 걸고 시작했다. **옵시디언에 의존하지 않는다.** TaskNotes가 로컬 HTTP API를 제공하지만 그것도 안 쓴다. 파일시스템만 읽고 쓴다.

덕분에 이 데몬은 GUI가 없는 곳에서도 돈다. 지금은 맥북에서 돌지만 라즈베리파이나 홈서버로 옮길 수 있고, 실제로 컨테이너로 옮겨본 적도 있다. 파이썬 3.9에 외부 의존성을 셋(`requests`, `PyYAML`, `python-dateutil`)으로 묶어둔 것도 그래서다.

웹훅 대신 폴링을 고른 것도 같은 맥락이다. 웹훅을 받으려면 외부에서 접근 가능한 공개 엔드포인트가 필요한데, **개인 할일 동기화 하나 때문에 서버를 열 이유가 없다.** 최대 1분 지연을 받아들이는 쪽이 낫다.

## 무엇이 오가는가

여기가 이 글에서 제일 실용적인 부분이다. 두 시스템은 개념이 다르게 생겨서 그대로 대응되지 않는 게 많다.

| TaskNotes | Todoist | 방향 | 비고 |
|---|---|---|---|
| 파일명(제목) | 제목 | ↔ | 제목 변경 = 파일 이름 변경 |
| 완료 | 체크 | ↔ | 완료일까지 |
| open / in-progress | **섹션** | ↔ | 미리 만들어둬야 함 |
| `scheduled`(일정) | `due` | ↔ | 날짜·시간 모두 |
| `due`(마감) | `deadline` | ✗ | **유료 전용 → 로컬 전용** |
| 소요시간(분) | duration | ↔ | 시간 지정된 것만 |
| 우선순위 | 1~4 | ↔ | |
| 태그 | 라벨 | ↔ | |
| 프로젝트 | **라벨** `프로젝트/…` | ↔ | 프로젝트를 안 만든다 |
| 하위작업 | 부모-자식 중첩 | ↔ | 부모가 미완료여야 |
| 반복 | 반복 | ↔(느슨) | 규칙만, 날짜는 각자 |
| 노트 딥링크 | **댓글** | → | 단방향 |

설명이 필요한 것들만 짚는다.

**상태를 섹션으로 표현한다.** Todoist에는 "진행 중"이라는 개념이 없다. 그래서 Inbox 안에 `Open`과 `In-progress` 섹션을 미리 만들어두고, 태스크를 그 섹션에 옮기는 것으로 상태를 표현한다. **이 섹션을 안 만들어두면 동작하지 않는다.** 완료는 섹션이 아니라 체크로 처리한다. 체크하면 Todoist 목록에서 사라지기 때문에 "Done 섹션"은 만들지 않는다.

**일정과 마감을 구분한다.** Todoist의 `due`는 "언제 할 것인가"에 가까워서 TaskNotes의 `scheduled`와 짝지었다. 진짜 마감(`deadline`)은 Todoist 유료 기능이라 무료 플랜에서는 동기화가 안 된다. 그래서 마감일은 볼트 안에서만 산다. 코드가 유료 기능 오류를 만나면 그 필드를 빼고 자동으로 재시도한다.

**프로젝트를 프로젝트로 안 쓴다.** `프로젝트/SaaS_전용망_POC` 같은 라벨로 표현한다. 이유는 아래 "밟은 함정"에 적었다. Todoist 라벨은 공백을 못 받아서 `_`로 치환한다.

**하위작업은 부모가 미완료일 때만 중첩된다.** 완료된 부모는 Todoist 목록에 없어서 자식을 매달 수 없다. 그럴 땐 라벨로 폴백한다. 부모가 아직 동기화 안 됐으면 추측해서 채우지 않고 다음 사이클로 미룬다 — **모르면 손대지 않는다**가 이 도구의 기본값이다.

**Todoist 태스크에 옵시디언 링크가 댓글로 붙는다.** 아이패드 Todoist에서 탭하면 해당 노트로 점프한다. 생성 시 한 번만 다는 단방향이라, 나중에 제목을 바꾸면 옛 링크가 깨질 수 있다.

## 설치하고 굴리기

파이썬 가상환경 하나 만들고 토큰 넣으면 끝이다.

```bash
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
cp config.example.yaml config.yaml
# config.yaml 에 Todoist API 토큰 입력
```

명령은 다섯 개다.

| 명령 | 하는 일 |
|---|---|
| `scan` | 토큰 없이 볼트만 파싱해서 결과 출력. 오프라인 검증 |
| `doctor` | 설정과 연결 점검 |
| `once --dry-run` | **아무것도 쓰지 않고 계획만 로그** |
| `once` | 한 번 동기화 |
| `run` | 주기 반복. 데몬이 이걸 실행 |
| `reset` | 모든 연결 정보 제거 + 상태 DB 초기화 |

첫 실행은 반드시 이 순서로 한다.

```bash
python -m tnsync.cli doctor            # 연결 확인
python -m tnsync.cli once --dry-run    # 계획 먼저 (중요)
python -m tnsync.cli once              # 실제 1회
```

`--dry-run`을 건너뛰지 말 것. 양방향 동기화의 첫 실행은 **양쪽에 이미 있는 것들을 어떻게 짝지을 것인가**를 결정하는 순간이고, 여기서 잘못 짝지으면 중복이 대량으로 생긴다. 제목이 같은 것끼리 먼저 연결하도록 해뒀지만 계획은 눈으로 봐야 한다.

상시 구동은 macOS라면 `launchd`다. 60초 주기, 부팅 시 자동 실행, 죽으면 재시작.

```bash
launchctl list | grep tnsync                    # 상태
launchctl kickstart -k gui/$(id -u)/<라벨>       # 코드 바꾼 뒤 재시작
tail -f tnsync.log                              # 로그
```

## macOS에서 반드시 물리는 것

**볼트가 `~/Documents` 안에 있으면 데몬이 파일을 못 읽는다.**

터미널에서 `once`는 잘 되는데 데몬으로 돌리면 `Operation not permitted`가 난다. macOS의 파일 접근 보호(TCC) 때문이다. 터미널 앱에는 이미 권한이 있지만 `launchd`가 띄운 파이썬에는 없다.

해결은 시스템 설정 → 개인정보 보호 및 보안 → **전체 디스크 접근 권한**에서 파이썬 실행 파일을 직접 추가하는 것이다. 숨은 경로라 `⌘⇧G`로 이동해야 한다.

```
/Library/Developer/CommandLineTools/Library/Frameworks/Python3.framework/Versions/3.9/bin/
```

**명령어로는 부여할 수 없다.** 애플 보안 정책이라 GUI에서 한 번 해줘야 한다. 이걸 모르면 "코드는 맞는데 데몬만 안 돈다"에서 몇 시간 날린다.

## 알고 써야 하는 제약

장점만 적으면 광고가 되니 안 되는 걸 다 적는다.

**최대 1분 지연.** 웹훅이 아니라 폴링이다. 그리고 **맥북(또는 대체 서버)이 켜져 있어야 한다.** 아이패드는 백그라운드 데몬을 못 돌리니 어딘가는 상시 켜져 있어야 한다.

**마감일은 동기화되지 않는다.** 무료 플랜 얘기다.

**반복 작업은 느슨하게만 맞는다.** 두 시스템의 반복 모델이 근본적으로 다르다. TaskNotes는 노트 하나에 완료한 회차 목록을 쌓고, Todoist는 완료하면 다음 날짜로 전진한다. 제목·우선순위·라벨·상태는 항상 맞추지만 **반복 규칙 자체는 만들 때 한 번만 변환한다.** 나중에 양쪽 규칙이 어긋나면 자동으로 병합하지 않고 경고만 남기고 멈춘다. 사람이 한쪽을 고쳐야 한다. 자동으로 맞추려다 노트가 자기 규칙과 모순되는 상태가 된 적이 있어서 이렇게 바꿨다.

**우선순위에 미세한 드리프트가 있다.** TaskNotes의 "없음"과 "보통"이 둘 다 Todoist의 1로 매핑된다. 그래서 Todoist에서 P2로 바꾸면 한 바퀴 돌고 나서 "보통"이 된다. 기본 태스크에 불필요한 우선순위 노이즈가 생기지 않게 하려고 일부러 그렇게 뒀다.

**태그와 라벨을 구분하지 않는다.** TaskNotes의 모든 태그가 라벨이 된다. 일부만 보내고 싶으면 필터를 추가해야 한다.

**개발 중에는 데몬을 내려야 한다.** 데몬과 수동 실행이 같은 상태 DB를 공유해서 충돌할 수 있다.

## 이게 왜 필요했나

기능 목록만 보면 "그냥 할일 동기화"인데, 만든 이유는 좀 다르다.

할일을 Todoist로 빼고 나니 **주말에 회고할 때 이번 주에 뭘 했는지의 절반이 볼트에 없었다.** 저널에는 무슨 생각을 했는지가 적혀 있는데 정작 무엇을 처리했는지는 다른 앱에 있다. 그러면 회고가 반쪽이 된다.

내 기록 시스템은 **토요일 회고 → 다음 주 행동 하나 → 매일 아침 일간 노트 → 실행 → 다시 회고**라는 고리로 돌아간다. 이 고리에서 "실행"만 볼트 밖에 있으면 고리가 끊기고, 끊긴 채로 두면 **기록만 쌓이고 행동은 안 바뀐다.**

도구를 나누는 건 쉽다. 나눈 걸 다시 붙이는 게 일이다.

만드는 과정에서 밟은 함정들 — 무한 루프, 반복 작업을 완료했더니 반복 자체가 끝나버린 것, 날짜를 미뤘을 뿐인데 없던 완료가 생긴 것 — 은 [[tnsync/tnsync-build|다음 글]]에 적었다.
